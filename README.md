# PowerGuide Bot — dev

Telegram-бот для создания презентаций: от описания и исходных материалов до готовых слайдов. Ветка `dev` содержит локальные доработки и новый способ генерации редактируемого PowerPoint через HTML/CSS.

После согласования содержания и выбора стиля пользователь выбирает один из двух режимов:

| Режим | Как строится презентация | Результат |
|---|---|---|
| **✏️ Редактируемый PPTX** | Gemini создаёт визуальный план и HTML/CSS, модель изображений — отдельные иллюстрации; локальный Chrome рассчитывает расположение объектов для экспорта в PowerPoint | PPTX и автономный HTML с кнопкой скачивания PPTX |
| **▶️ Стандартная генерация** | Модель изображений рисует слайды; бот проверяет текст и собирает файлы | Альбом изображений, PDF и отдельный PPTX с текстом и исходными фотографиями |

В новом PPTX текст, поддерживаемые фигуры и элементы схем представлены отдельными объектами PowerPoint. Фон и сгенерированные иллюстрации остаются растровыми изображениями. В стандартном PPTX оформление упрощено: художественный результат сохраняется в изображениях и PDF.

## Сценарий пользователя

1. Описать презентацию и приложить материалы: PDF, DOCX, PPTX, XLSX, TXT, CSV или изображения.
2. Ответить на недостающие вопросы и подтвердить требования.
3. Получить техническое задание, подготовленные данные и план слайдов.
4. При необходимости изменить отдельные слайды и добавить фотографии с подписями.
5. Выбрать готовый стиль или прислать свой референс. Для своего оформления — подтвердить сгенерированный фон.
6. Выбрать редактируемый PPTX или стандартную генерацию.
7. Получить готовые файлы. При сбое продолжить незавершённый этап через «Повторить»; для новой ветки также доступен явный переход к стандартной генерации.

## Что находится в репозитории

Код обеих веток, опросник, тесты, зависимости с lock-файлом и пример конфигурации.

**Рабочие промпты `prompts/` и шесть готовых стилей `presets/` не публикуются.** Для полного запуска их нужно получить у владельца проекта либо подготовить свои. Без рабочих промптов доступны изучение кода и запуск тестов, но диалог генерации целиком не работает. Готовые стили необязательны: без них остаётся выбор своего референса или генерация фона.

Ключи API, `.env`, база данных, пользовательские материалы, результаты сессий, архивы экспериментов и настройки доступа к серверу в репозиторий не входят. Тексты инструкций новой HTML/PPTX-ветки также исключены: `bot/editable/prompts.py` содержит только загрузчик трёх закрытых файлов, перечисленных ниже.

## Изучение кода и тесты без API-ключей

Нужны Python 3.12+ и `uv`.

```bash
git clone --branch dev https://github.com/Lucifercute/powerguide-bot.git powerguide-bot-dev
cd powerguide-bot-dev
uv sync --locked
uv run python -m unittest discover -s tests -v
```

Тесты используют временные БД и подменённые обращения к Telegram/моделям. Они не расходуют API-квоту и не требуют Chrome. Проверяются обе ветки диалога, сохранение выбора, повторные нажатия, отмена, восстановление после ошибок и структура PPTX.

## Полный локальный запуск

Дополнительно нужны:

- отдельный Telegram-бот и его токен;
- настроенные ключи Google Gemini/Vertex AI и доступные вашему проекту модели;
- рабочие файлы `prompts/`;
- Chrome или Chromium для редактируемого PPTX;
- при необходимости LibreOffice для чтения Word/PowerPoint через PDF и Tavily для поиска в интернете.

```bash
cp .env.example .env
# Заполнить .env своими ключами и именами доступных моделей.
# Разместить рабочие промпты в prompts/, стили — при наличии — в presets/.
uv run python scripts/check_setup.py
uv run python -m bot
```

Один Telegram-токен должен обслуживаться одним процессом polling. Для отдельной копии разработки используйте отдельный токен и локальную БД. Запуск через терминал или фоновый процесс не отображается как запущенная конфигурация Run в PyCharm.

### Настройки

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен собственного Telegram-бота |
| `GEMINI_API_KEY` | Ключ Gemini API; текущий загрузчик конфигурации требует его и при использовании только Vertex для текста |
| `VERTEX_API_KEY` | Ключ Vertex AI для изображений и/или текста |
| `GOOGLE_CLOUD_PROJECT` | Идентификатор вашего Google Cloud проекта, если требуется используемым режимом Vertex AI |
| `GEMINI_TEXT_MODELS` | Модели Gemini для текста; пустое значение отключает этот список |
| `VERTEX_TEXT_MODELS` | Модели Vertex AI для текста |
| `IMAGE_MODELS` | Модели изображений в порядке попыток |
| `EDITABLE_PPTX_ENABLED` | `1` показывает выбор режимов после оформления; `0` сохраняет прежний сценарий для новых сессий |
| `EDITABLE_CHROME_PATH` | Путь к Chrome/Chromium; на macOS стандартный Google Chrome находится автоматически, на Linux ищется в PATH |
| `DB_PATH`, `FILES_DIR` | Локальная БД и файлы сессий |
| `PROMPTS_DIR`, `PRESETS_DIR` | Каталоги рабочих промптов и готовых стилей |
| `TAVILY_API_KEY` | Необязательный ключ веб-поиска; пустое значение отключает поиск |
| `LIBREOFFICE_PATH` | Необязательный путь к `soffice`; без LibreOffice Word/PowerPoint читаются как текст |

Имена моделей в примере соответствуют конфигурации, использовавшейся при разработке. Их доступность зависит от вашего Google Cloud проекта. Вызовы моделей могут расходовать платную квоту.

### Рабочие промпты

Файлы `.md` находятся непосредственно в `prompts/`. Они перечитываются при выполнении этапа, поэтому изменения текста не требуют перезапуска процесса.

```text
00_survey_analysis.md        01_tz.md
02_data.md                   02a_search_queries.md
03-1_plan.md                 03-2_plan_check.md
04_background.md             04a_background_fields.md
04b_background_edit.md       04c_background_redraw.md
04d_background_fields_redraw.md
05_style.md                  06_descriptions.md
06a_user_images.md           07_slide.md
07a_slide_reference.md       07b_user_image_area.md
07c_no_user_image.md         08_text_check.md

# Дополнительно для редактируемого PPTX:
editable_visual_plan.md
editable_html.md
editable_image.md
```

### Готовые стили

```text
presets/
  1/
    preview.jpg
    background.png    # либо background.jpg
    style.md
  2/
    ...
```

Бот использует исходный растровый фон выбранного пресета. В новой ветке этот фон встраивается в HTML и PPTX; модель формирует поверх него текст, схемы и иллюстрации. Для подготовки собственных пресетов есть `scripts/build_presets.py`.

## Архитектура

```text
bot/
  __main__.py          запуск и сборка зависимостей
  handlers.py          описание, материалы, план, фотографии, оформление
  generation_modes.py  выбор режима и восстановление нужной ветки
  generation.py        стандартная генерация и выдача файлов
  editable/
    service.py         визуальный план → HTML → иллюстрации → PPTX
    prompts.py         загрузчик закрытых инструкций новой ветки
    models.py          схемы структурированных ответов
    html.py            проверка разметки и упаковка автономного HTML
    browser.py         локальный Chrome, проверка и сохранение PPTX
    export-pptx.js     перенос текста и геометрии DOM в объекты OOXML
  pipeline.py          подготовка заданий и запросов к моделям
  llm.py               клиенты моделей, повторы и запасные модели
  db.py                сессии, ответы, артефакты, исходные файлы
  jobs.py              владение задачами, отмена и защита от повторного запуска
  runtime.py           ресурсы сессий и изображения
  sources.py           чтение файлов и конвертация через LibreOffice
  export.py            PDF и текстовый PPTX стандартной ветки
  plan.py              разбор и редактирование согласованного плана
  presets.py           загрузка подготовленных стилей
  questions.py         опросник
  search.py            веб-поиск
  textcheck.py          проверка текста растровых слайдов
  user_images.py       фотографии пользователя
```

Выбранный режим сохраняется в SQLite как артефакт `generation_mode`. Маркер окончания добавления фотографий `slide_images_done` не считается началом генерации: новые сессии доходят до выбора режима. Старые сессии с уже подготовленными описаниями или начатыми слайдами продолжают стандартную ветку.

Новая ветка сохраняет запросы, ответы, визуальный план, HTML, иллюстрации и результаты экспорта в `data/sessions/<id>/editable/`. Завершённые этапы используются повторно; сбой экспорта сам по себе не требует заново создавать текст и картинки. При некорректном ответе предусмотрены ограниченные попытки исправления. При выходе текста за края предусмотрена отдельная стадия исправления вёрстки.

После перезапуска процесса незавершённая сессия продолжается по сообщению пользователя или кнопке «Повторить». Автоматического запуска всех незавершённых задач при старте нет. `/cancel` и новая презентация отменяют текущую задачу.

## Проверки и ограничения

- 32 автоматических теста, включая реальный порядок шагов перед выбором режима.
- Экспорт проверен через локальный Chrome на форматах 16:9 и 4:3; отдельно проверены исходный фон, редактируемый текст и скруглённые плашки.
- Контрольная презентация прошла генерацию через настроенные модели, экспорт в PPTX и независимое отображение через LibreOffice.
- Экспорт поддерживает ограниченный набор HTML/CSS/SVG. Сложные фильтры, маски, эффекты и произвольная веб-вёрстка не переносятся полностью. Возможны отличия между просмотрщиками PowerPoint.
- Автоматическая проверка структуры и границ текста не заменяет визуальную проверку дизайна и фактов.

## Ветка разработки и сервер

`dev` предназначена для изучения и проверки новых возможностей. Публикация этой ветки не меняет `main` и не обновляет работающий сервер.

Унаследованные Docker-файлы и скрипты сервера сохранены для истории проекта. Текущий Dockerfile не устанавливает Chrome; новый экспорт следует проверять локальным запуском по инструкции выше. Скрипт `scripts/deploy.sh` предназначен для `main` и требует отдельной закрытой конфигурации `scripts/server.sh`. Для знакомства с `dev` серверный деплой не нужен.
