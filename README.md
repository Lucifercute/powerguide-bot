# PowerGuide Bot

Telegram-бот, который делает растровую презентацию с помощью ИИ: от короткого описания до готового PDF.

Пользователь описывает презентацию своими словами и присылает исходные данные. Бот уточняет недостающее, собирает техническое задание, ищет информацию в открытых источниках, предлагает план, рисует фон, генерирует слайды и проверяет текст на них.

## Как это работает

1. **Описание.** Пользователь в свободной форме рассказывает, о чём будет презентация.
2. **Исходные данные.** Файлы (PDF, Word, Excel, PowerPoint, TXT, CSV, картинки) и/или текстовый комментарий.
3. **Анализ.** Модель находит в описании и файлах ответы на вопросы опросника. Бот задаёт по одному только те вопросы, на которые ответа нет; любой можно пропустить. В конце пользователь проверяет и при необходимости исправляет свои ответы.
4. **Техническое задание** по ответам.
5. **Структура данных:** факты из файлов заказчика и веб-поиска (Tavily) с указанием источников.
6. **План презентации.** Пользователь принимает его или присылает исправленный `.txt`.
7. **Дизайн.** Можно прислать картинку-референс стиля. Бот рисует фон, пользователь принимает его или просит перерисовать.
8. **Слайды.** Описание каждого слайда, затем генерация изображений. Первый слайд прикладывается к остальным как образец, чтобы стиль был единым.
9. **Проверка текста.** Модель «вслепую» переписывает текст со слайда, код сравнивает его с ожидаемым по словам и сообщает пользователю о возможных опечатках.
10. **Результат:** альбом слайдов и PDF.

## Технические решения

- **Состояние в SQLite.** Результат каждого шага сохраняется, поэтому после сбоя или перезапуска бот продолжает с того же места и не тратит повторно платные запросы.
- **Повторы и запасные модели.** При перегрузке или исчерпании квоты запрос повторяется с паузой, затем уходит к следующей модели из списка.
- **Word и PowerPoint → PDF** через LibreOffice в headless-режиме, чтобы модель видела картинки и диаграммы, а не только текст. Перед конвертацией формат файла проверяется по содержимому; конвертация запускается без shell, с таймаутом и отдельным временным профилем.
- **Структурированные ответы модели** (JSON по схеме, проверка через Pydantic) там, где результат обрабатывает код.
- **Промпты и опросник — во внешних файлах.** Они перечитываются при каждом обращении, поэтому их можно править без перезапуска бота.
- **Telegram:** aiogram 3, long polling.

## Стек

Python 3.12, aiogram 3, aiosqlite, google-genai (Gemini API и Vertex AI), Tavily, python-docx, python-pptx, openpyxl, img2pdf, LibreOffice, uv.

## Структура проекта

```
bot/
  __main__.py   запуск бота
  config.py     настройки из переменных окружения
  handlers.py   диалог с пользователем: опрос, кнопки, шаги
  pipeline.py   промпты и обращения к моделям
  llm.py        клиенты Gemini: повторы, запасные модели
  sources.py    приём файлов, извлечение текста, конвертация в PDF
  search.py     веб-поиск через Tavily
  textcheck.py  сравнение текста на слайде с ожидаемым
  export.py     сборка PDF из слайдов
  db.py         SQLite: сессии, ответы, результаты шагов, файлы
  questions.py  загрузка опросника
questions.yaml  вопросы опросника
```

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). LibreOffice необязателен: без него Word и PowerPoint читаются только как текст.

```bash
uv sync
cp .env.example .env   # заполнить ключи
uv run python -m bot
```

Переменные окружения (подробнее в `.env.example`):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота от @BotFather |
| `GEMINI_API_KEY` | ключ Gemini API (AI Studio) |
| `VERTEX_API_KEY` | ключ Vertex AI: генерация изображений и платные текстовые модели |
| `GEMINI_TEXT_MODELS`, `VERTEX_TEXT_MODELS`, `IMAGE_MODELS` | списки моделей в порядке попыток |
| `TAVILY_API_KEY` | необязательно: без него шаг данных работает без веб-поиска |
| `LIBREOFFICE_PATH` | необязательно: путь к `soffice`, если он не находится сам |

## Сервер

Боевой бот работает на сервере в Docker (`Dockerfile`, `docker-compose.yml`): `.env`, `data/` и `prompts/` монтируются с хоста, контейнер перезапускается сам после сбоя и перезагрузки. Локально для разработки запускается отдельный бот со своим токеном и своей базой: один токен нельзя опрашивать из двух мест сразу.

| Скрипт | Что делает |
|---|---|
| `scripts/deploy.sh` | пушит `main`, на сервере `git pull` и пересборка контейнера; промпты — через `sync_prompts.sh`. С незакоммиченными изменениями не запускается |
| `scripts/sync_prompts.sh` | только промпты и готовые стили; перезапуск не нужен, бот читает их при каждом обращении |
| `scripts/snapshot.sh` | копирует базу и файлы сессий с сервера в `snapshots/<дата>/` для отладки; локальная `data/` не меняется |

Адрес сервера и ключ SSH — в `scripts/server.sh` (не в git, шаблон — `scripts/server.sh.example`). Логи: `docker logs -f powerguide-bot` на сервере.

## Промпты

Рабочие промпты не входят в репозиторий. Бот ищет их в папке `prompts/` (путь меняется переменной `PROMPTS_DIR`), по одному файлу `.md` на шаг: `00_survey_analysis`, `01_tz`, `02_data`, `02a_search_queries`, `03-1_plan`, `04_background`, `04a_background_fields`, `05_style`, `06_descriptions`, `07_slide`, `07a_slide_reference`, `08_text_check`.

## Готовые стили

На шаге дизайна бот показывает превью готовых стилей и кнопки «Стиль N». Выбранный стиль заменяет генерацию фона (04) и стиля (05): берутся подготовленный фон и текст стиля, фон сразу считается принятым. Свой референс и «Пропустить» работают как раньше.

Стили лежат в `presets/<N>/` (`preview.jpg`, `background.png|jpg`, `style.md`), в репозиторий не входят, как и промпты. Собираются из папки с файлами `стильN.txt`, `стильN.png|jpg`, `Ref-preview (N).png`; фон обрезается до 16:9, превью ужимается:

```bash
uv run python scripts/build_presets.py ~/Desktop/Prez-ref
```
