# PowerGuide Bot

## Локальный Telegram Mini App — пилот

Добавлены React/TypeScript-интерфейс, FastAPI и отдельный Python-обработчик заданий.
Чат и приложение используют общие операции генерации, существующие Gemini / Vertex AI,
проверки и экспорт. Серверный деплой не выполняется.

Первый запуск из основной папки проекта, ветка `dev`:

```bash
uv sync --locked
npm --prefix frontend ci
npm --prefix frontend run build
uv run python scripts/run_miniapp.py
```

Откройте **http://127.0.0.1:8000** и нажмите «Открыть локальную версию».
Локальный пользователь по умолчанию имеет ID `1`; ему не отправляются сообщения
в Telegram. Для первого просмотра без запуска обработчика моделей используйте
`uv run python scripts/run_miniapp.py --no-worker`.
Для другого порта добавьте `--port 8001`. Остановка всех запущенных компонентов — Ctrl+C.

Используются существующие локальные `DB_PATH`, `FILES_DIR`, промпты, стили и ключи
из `.env`. Создание/сохранение черновика и загрузка файлов не вызывают модели;
«Изучить материалы» и следующие этапы используют API-квоту.
При первом запуске схема SQLite расширяется без удаления старых сессий.
Перед внедрением сохранены исходный код и резервная копия SQLite в соседней папке
`../powerguide-local-backups/before-miniapp-20261112-193911/`.
Архив содержит локальные настройки и не предназначен для публикации.

### Что доступно

- Описание, исходные файлы, формат 16:9/4:3 и сохранение черновика.
- Анализ материалов и единая форма уточнений с найденными моделью ответами.
- План по слайдам: правка текста, свои изображения и подписи к ним.
- Схемы можно описывать обычным текстом: ручные строки «Блоки:» и «Связи:» для сохранения
  не требуются. Визуальная структура подготавливается моделью на этапе генерации.
- Готовые стили, свой референс, согласование фона и один дополнительный вариант.
- Стандартная презентация или экспериментальный редактируемый PPTX/HTML.
- Прогресс, очередь, отмена, явное продолжение прерванного этапа.
- История, предпросмотр и скачивание готовых файлов, удаление проекта с материалами.

На аккаунт приходится одна незавершённая презентация. Создание новой требует
подтверждения отмены предыдущей. Проект чата продолжается в чате, проект Mini App —
в приложении. Завершённые проекты обоих интерфейсов видны в истории.
Для старых растровых сессий, созданных до сохранения PDF/PPTX на диск, доступны
сохранённые изображения слайдов; прежние файлы также остаются в чате Telegram.

Для пилота сохранены ограничения: до 10 слайдов, до 10 исходных файлов по 20 МБ,
изображения до 10 МБ. По умолчанию допускаются три новые генерации пользователя
за сутки **UTC** и три одновременно выполняющиеся задачи всего.
Квота учитывается при первом задании проекта; явный повтор не списывает новый запуск,
но новый запрос к провайдеру при повторе может расходовать API-квоту.
Удаление проекта не обнуляет суточный счётчик. Исходники и результаты сохраняются
до удаления владельцем; при работающем обработчике файлы удаляются после остановки задачи.

### Проверка внутри Telegram — после локальной проверки браузера

Для теста **в обычном браузере без Telegram, регистрации и пароля** доступен вход
по персональному приглашению. Это тот же интерфейс с отдельным аккаунтом и общей
настраиваемой квотой генераций. Владелец ссылки получает доступ к этому тестовому
аккаунту; не публикуйте её в открытых каналах.

```bash
# Отдельный порт позволяет сохранить ваш текущий локальный просмотр на 8000.
# --no-worker указывайте, только если основной обработчик уже работает с этой базой.
uv run python scripts/run_miniapp.py --share --port 8001 --no-worker
cloudflared tunnel --url http://127.0.0.1:8001

# Подставьте HTTPS-адрес, который выдал туннель:
uv run python scripts/test_invite.py create --url https://example.trycloudflare.com --name Тестировщик
```

Отправьте товарищу **полную** выданную ссылку с `#invite=...`. Вход произойдёт
автоматически, затем приглашение исчезнет из адресной строки. Повторное открытие
этой ссылки ведёт в тот же аккаунт. Стандартный срок — 48 часов; `--hours` позволяет
выбрать от 1 до 168 часов. Сессия браузера длится до 12 часов: после её истечения
нужно снова открыть исходную ссылку. В SQLite хранится только хеш приглашения.
Проекты приглашённого пользователя отделены от локального и Telegram-аккаунтов;
отправка в Telegram для такого пользователя отключена.

```bash
uv run python scripts/test_invite.py list
uv run python scripts/test_invite.py revoke ID_ПРИГЛАШЕНИЯ
```

Отзыв сразу запрещает новые запросы и отменяет незавершённые проекты аккаунта.
Приглашения принимаются только в режиме `--share` (`WEB_INVITES_ENABLED=1`), в котором
локальный вход отключён. Ссылка работает, пока запущены приложение и туннель на вашем
компьютере. Это локальный тестовый доступ без переноса на сервер.

Для проверки Mini App внутри Telegram:

Используйте только локального тестового бота. Сначала остановите прежний локальный
polling-процесс этого бота: два процесса не должны опрашивать один токен.

1. Задайте в локальном `.env` `PILOT_ALLOWED_IDS=123456789,...` — числовые Telegram ID
   участников. Пустой список закрывает Telegram-доступ всем.
2. Поднимите временный туннель: `cloudflared tunnel --url http://127.0.0.1:8000`.
3. Запишите полученный HTTPS-адрес в локальный `MINIAPP_URL`.
4. Запустите `uv run python scripts/run_miniapp.py --telegram --with-bot`.
5. Отправьте `/start` тестовому боту и нажмите «Открыть приложение».

Этот сценарий не требует изменения боевого бота или сервера. Адрес Quick Tunnel
меняется при перезапуске туннеля. Не используйте браузерный локальный вход через
туннель: флаг `--telegram` отключает его на всём сервере.
Кнопка открытия приложения использует обычный HTTPS Web App URL; дополнительная
настройка Main Mini App в BotFather для этой кнопки не требуется.

В Mini App сервер проверяет подпись и возраст `initData`, выдаёт HttpOnly-сессию
и проверяет список допуска и владельца каждого проекта/файла. Сгенерированный HTML
просматривается отдельно в sandbox без скриптов. Скачиваемый автономный HTML
сохраняет штатные функции экспортёра.

Для самостоятельного запуска компонентов вместо общего скрипта:

```bash
# Требуется одинаковая конфигурация .env; WEB_SESSION_SECRET — случайная строка 32+ символов.
uv run uvicorn bot.web.api:create_app --factory --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
uv run python -m bot.web.worker
PILOT_ENABLED=1 uv run python -m bot
```

Обычный `python -m bot` при `PILOT_ENABLED=0` сохраняет прежний запуск.
Для одновременной работы чата и Mini App с общей очередью обязательно включите
`PILOT_ENABLED=1` или используйте общий скрипт с `--with-bot`.
`STANDARD_GENERATION_ENABLED=0` скрывает стандартный режим для новых генераций;
уже выбранные стандартные проекты сохраняют свой режим. Редактируемый режим
управляется существующим `EDITABLE_PPTX_ENABLED`.

### Разработка и проверки Mini App

Общий сервис находится в `bot/presentation.py`, сервер и очередь — в `bot/web/`,
интерфейс — в `frontend/`. FastAPI публикует контракт в `/docs` и `/openapi.json`.
Основные маршруты `/api/v1`: `auth/*`, `me`, `projects`, `presets`;
действия проекта — `POST projects/{id}/commands`, загрузки — `POST projects/{id}/uploads`.
Команды содержат `revision`: устаревшие действия отклоняются, интерфейс обновляет проект.
API не вызывает модели. Обработчик заданий атомарно забирает записи SQLite;
единственность процесса защищена OS-блокировкой. После перезапуска выполнявшиеся
задания отмечаются прерванными и требуют кнопки продолжения; ожидающие задания
сохраняются в очереди. Отправка результата — отдельное задание с учётом отправленных файлов.

При разработке интерфейса можно запустить `npm --prefix frontend run dev`:
Vite проксирует `/api` на локальный порт 8000. После правок для основного запуска
пересоберите `frontend/dist` командой `npm --prefix frontend run build`.

```bash
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend run build
npm --prefix frontend test
```

Python-тесты и браузерные тесты Mini App работают с временными базами и тестовыми
ответами моделей, без платных запросов. Playwright использует установленный Google Chrome
с отдельным временным профилем; тесты экспортёра тоже запускают Chrome.
Снимки интерфейса сохраняются локально в `snapshots/miniapp-ui/`.
Новые тесты проверяют полный стандартный конвейер, контракт редактируемого результата,
загрузки, владельца, подписи/срок входа, запрет локального входа через туннель,
квоты, конкурентный захват заданий, миграции и остановку перед удалением файлов.

Публичная регистрация браузерных пользователей, платежи и редактирование готовых слайдов
в приложении пока не реализованы; для закрытого браузерного теста есть персональные
приглашения, описанные выше. Адаптивные экраны и HTTP API уже отделены от Telegram SDK:
для сайта потребуется добавить способ входа и связать его с общей историей.
Проверка реальных Google-запросов и поведения внутри Telegram выполняется отдельно
при вашей приёмке; тестовые результаты не выдаются за новую генерацию через API.


Telegram-бот, который делает растровую презентацию с помощью ИИ: от короткого описания до готового PDF.

Пользователь описывает презентацию своими словами и присылает исходные данные. Бот уточняет недостающее, собирает техническое задание, ищет информацию в открытых источниках, предлагает план, рисует фон, генерирует слайды и проверяет текст на них.

## Как это работает

1. **Описание.** Пользователь в свободной форме рассказывает, о чём будет презентация.
2. **Исходные данные.** Файлы (PDF, Word, Excel, PowerPoint, TXT, CSV, картинки) и/или текстовый комментарий.
3. **Анализ.** Модель находит в описании и файлах ответы на вопросы опросника. Бот задаёт по одному только те вопросы, на которые ответа нет; любой можно пропустить. В конце пользователь проверяет и при необходимости исправляет свои ответы.
4. **Техническое задание** по ответам.
5. **Структура данных:** факты из файлов заказчика и веб-поиска (Tavily) с указанием источников.
6. **План презентации.** Пользователь принимает его или присылает исправленный `.txt`.
7. **Дизайн.** Можно прислать картинку-референс стиля. Бот рисует фон, пользователь принимает его или просит перерисовать.
8. **Слайды.** Описание каждого слайда, затем генерация изображений. Первый слайд прикладывается к остальным как образец, чтобы стиль был единым.
9. **Проверка текста.** Модель «вслепую» переписывает текст со слайда, код сравнивает его с ожидаемым по словам и сообщает пользователю о возможных опечатках.
10. **Результат:** альбом слайдов, PDF и отдельный PPTX с редактируемым текстом и исходными изображениями. PPTX имеет простое оформление; диаграммы и схемы из плана передаются текстом, а не редактируемыми фигурами.

## Технические решения

- **Состояние в SQLite.** Результат каждого шага сохраняется, поэтому после сбоя или перезапуска бот продолжает с того же места и не тратит повторно платные запросы.
- **Повторы и запасные модели.** При перегрузке или исчерпании квоты запрос повторяется с паузой, затем уходит к следующей модели из списка.
- **Word и PowerPoint → PDF** через LibreOffice в headless-режиме, чтобы модель видела картинки и диаграммы, а не только текст. Перед конвертацией формат файла проверяется по содержимому; конвертация запускается без shell, с таймаутом и отдельным временным профилем.
- **Структурированные ответы модели** (JSON по схеме, проверка через Pydantic) там, где результат обрабатывает код.
- **Промпты и опросник — во внешних файлах.** Они перечитываются при каждом обращении, поэтому их можно править без перезапуска бота.
- **Telegram:** aiogram 3, long polling.

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). LibreOffice необязателен: без него Word и PowerPoint читаются только как текст.

```bash
uv sync
cp .env.example .env   # заполнить ключи
uv run python -m bot
```

Переменные окружения (подробнее в `.env.example`):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота от @BotFather |
| `GEMINI_API_KEY` | ключ Gemini API (AI Studio) |
| `VERTEX_API_KEY` | ключ Vertex AI: генерация изображений и платные текстовые модели |
| `GEMINI_TEXT_MODELS`, `VERTEX_TEXT_MODELS`, `IMAGE_MODELS` | списки моделей в порядке попыток |
| `TAVILY_API_KEY` | необязательно: без него шаг данных работает без веб-поиска |
| `LIBREOFFICE_PATH` | необязательно: путь к `soffice`, если он не находится сам |

## Сервер

Боевой бот работает на сервере в Docker (`Dockerfile`, `docker-compose.yml`): `.env`, `data/` и `prompts/` монтируются с хоста, контейнер перезапускается сам после сбоя и перезагрузки. Локально для разработки запускается отдельный бот со своим токеном и своей базой: один токен нельзя опрашивать из двух мест сразу.

| Скрипт | Что делает |
|---|---|
| `scripts/deploy.sh` | пушит `main`, на сервере `git pull` и пересборка контейнера; промпты — через `sync_prompts.sh`. С незакоммиченными изменениями не запускается |
| `scripts/sync_prompts.sh` | только промпты и готовые стили; перезапуск не нужен, бот читает их при каждом обращении |
| `scripts/snapshot.sh` | копирует базу и файлы сессий с сервера в `snapshots/<дата>/` для отладки; локальная `data/` не меняется |

Адрес сервера и ключ SSH — в `scripts/server.sh` (не в git, шаблон — `scripts/server.sh.example`). Логи: `docker logs -f powerguide-bot` на сервере.

## Промпты

Рабочие промпты не входят в репозиторий. Бот ищет их в папке `prompts/` (путь меняется переменной `PROMPTS_DIR`), по одному файлу `.md` на шаг: `00_survey_analysis`, `01_tz`, `02_data`, `02a_search_queries`, `03-1_plan`, `04_background`, `04a_background_fields`, `05_style`, `06_descriptions`, `07_slide`, `07a_slide_reference`, `08_text_check`.

## Готовые стили

На шаге дизайна бот показывает превью готовых стилей и кнопки «Стиль N». Выбранный стиль заменяет генерацию фона (04) и стиля (05): берутся подготовленный фон и текст стиля, фон сразу считается принятым. Свой референс и «Пропустить» работают как раньше.

Стили лежат в `presets/<N>/` (`preview.jpg`, `background.png|jpg`, `style.md`), в репозиторий не входят, как и промпты. Собираются из папки с файлами `стильN.txt`, `стильN.png|jpg`, `Ref-preview (N).png`; фон обрезается до 16:9, превью ужимается:

```bash
uv run python scripts/build_presets.py ~/Desktop/Prez-ref
```

## Локальные изменения и проверка

`/cancel` и начало новой презентации останавливают выполняющуюся задачу старой сессии,
включая ожидание повторных запросов. Уже отправленный запрос может быть обработан и оплачен
на стороне провайдера: отмена прекращает ожидание и дальнейшие запросы бота.
Отменённая сессия не переводится обратно в завершённую.

Загрузка исходных файлов и кнопка «Готово» используют одну блокировку на сессию.
Другие пользователи загружают файлы независимо. Описания слайдов проверяются по полному
набору и порядку номеров согласованного плана; пропуски, дубли и лишние слайды
не сохраняются как успешный результат. Старое неполное описание удаляется при повторе,
чтобы его можно было подготовить заново. Готовые изображения повторно не генерируются.

После сбоя отправьте сообщение в активную сессию или нажмите «Повторить»:
автоматического возобновления задач при старте процесса нет. Сохранённые этапы используются повторно.

Дополнительный PPTX содержит настоящие текстовые поля и исходные картинки.
Он предназначен для правки содержания; художественное оформление остаётся в растровом PDF.
Десятичные разделители теперь учитываются при проверке текста слайдов.

Проверки без Telegram, сетевых запросов и оплаты моделей:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

### Выбор редактируемого PPTX в локальном боте

При `EDITABLE_PPTX_ENABLED=1` после выбора готового стиля или принятия своего фона
появляются кнопки «✏️ Редактируемый PPTX» и «▶️ Стандартная генерация».
Стандартная ветка сохраняет прежние результаты: изображения слайдов, PDF и текстовый PPTX.
Редактируемая ветка строит визуальный план по согласованному содержанию, HTML/CSS,
отдельные иллюстрации через настроенную модель изображений и экспортирует объекты в PPTX.
Бот отправляет PPTX и автономный HTML с кнопкой скачивания PowerPoint.
Текст, фигуры и схемы редактируются; фон и иллюстрации остаются растром.

Новый режим по умолчанию выключен; он включён только в локальном `.env`.
Используются существующие настройки `GEMINI_TEXT_MODELS`, `VERTEX_TEXT_MODELS`, `IMAGE_MODELS`.
Для экспорта необходим установленный Chrome/Chromium: на macOS находится автоматически,
другой путь задаётся в `EDITABLE_CHROME_PATH`. Браузер запускается с временным профилем,
без внешних ресурсов. Зависимости синхронизируются через `uv sync --locked`.

Выбранная ветка хранится в артефакте `generation_mode`, состояние выбора — в `waiting_for`.
Старая сессия с готовыми описаниями/начатыми слайдами продолжает стандартную генерацию.
После сбоя нового режима «Повторить» использует сохранённые этапы, а кнопка
«Перейти к стандартной генерации» явно меняет ветку. Автоматической подмены результата нет.
Файлы и точные текстовые запросы сохраняются в `data/sessions/<id>/editable/`:
`input.json`, запросы/ответы этапов, `visual-plan.json`, `deck.json`, иллюстрации,
`presentation.html`, `presentation.pptx`, `export-check.json`, `completed.json`.
HTML проверяется на структуру и геометрию текста; при выходе текста за границы
предусмотрена одна дополнительная стадия исправления вёрстки. Неполный результат не отправляется.

Проверки: ` .venv/bin/python -m unittest discover -s tests -v` (без сетевых запросов).
Браузерный экспорт отдельно проверен на форматах 16:9 и 4:3, включая точный фон,
редактируемый текст, изображения и скруглённые плашки. Визуальная идентичность
в разных версиях PowerPoint не гарантируется: поддерживается ограниченный набор HTML/CSS/SVG.

Снимок перед внедрением: `../powerguide-local-backups/before-editable-mode-20261112-003644/`.
Для отключения выбора достаточно установить `EDITABLE_PPTX_ENABLED=0` и перезапустить
локальный процесс. Уже выбранные редактируемые сессии продолжают свою ветку.
Для полного отката используйте `RESTORE.txt` в снимке. Сервер не обновлялся.

Экспорт скруглённых карточек учитывает собственный border-radius изображения и контур
родительских контейнеров с overflow:hidden/clip, в том числе вложенных. Обрезка фона
подписи и изображений записывается как нативная геометрия PPTX; текст остаётся
редактируемым. Картинка с object-fit:contain не получает скругление родителя, если её
видимая область не пересекает этот контур. Регрессионные проверки: tests/test_editable_clipping.py.

Проверка разнообразия композиции измеряет крупные текстовые панели в DOM, независимо
от названий форм. При их доминировании на большинстве содержательных слайдов общий
этап layout-repair отправляет замечания той же модели. Это эвристика, а не полная
оценка дизайна или сохранности смысла. Реальные прогоны можно повторять изолированно:
`.venv/bin/python -m scripts.test_editable_session --session 37 --output snapshots/my-test --audit-baseline`.
Новая папка означает новую генерацию через настроенные API (с расходом квоты);
существующая папка продолжает сохранённые этапы. Рабочая БД и Telegram не изменяются.

### Единая локальная рабочая папка

Разработка ведётся в `powerguide-bot`, ветка `dev`. Здесь находятся локальный `.env`,
виртуальное окружение `.venv`, рабочая БД `data/bot.db`, сессии, промпты, стили и
эксперименты `snapshots/`. Запуск: `.venv/bin/python -m bot`.
Отдельная рабочая папка `powerguide-bot-dev` больше не используется.

Порядок работы: изменить и протестировать локально; после явного одобрения владельца
зафиксировать готовые изменения, перенести их в `main` и выполнить серверный деплой.
Само переключение/публикация ветки `dev` сервер не обновляет. `scripts/deploy.sh`
по-прежнему допускает деплой только из чистой ветки `main`.

Отложенные изменения шрифтов и компоновки сохранены в
`snapshots/pending-dev-changes/fonts-layout.patch`. Они требуют отдельной проверки
через штатные API и автоматически не включаются. Результаты прежних экспериментов
доступны в `snapshots/prompt-style-v2-comparison/` и `snapshots/layout-fonts-v3/`.
Папка `layout-fonts-v3` содержит диагностические локальные переработки, а не новый API-прогон.
